二

精简删除的功能

3 个模块

以下功能在 Snippets 场景下不需要，已删除以适配 32KB 限制。如需这些功能，请使用官方原版 4.4.5子后端_worker.js（59KB，仅 Worker 部署）。

删除
链式代理（Socks5 / HTTP 上游）
约 2,800 字节

删除的函数：

socks5Handshake · httpConnectHandshake · chainConnect
parseUpstreamAddr · parseUpstreamEntries
inlineChain 路径内嵌链式（/socks5= / /http=）
ChainEnabled / Upstream 配置项
  • 影响：失去 Socks5/HTTP 上游链式代理能力
  • 替代：Snippets 场景下反代/直连已足够；需链式用 Worker 版
  • forceProxy：简化为 outbound === 'global' || !!inlineExit（去掉 chainOn 条件）
删除
D1 数据库绑定
约 1,500 字节

删除的机制：

runtimeEnv · env.Senflare · db.prepare
confGeneration（推送代数校验）
nodeConfFailUntil（D1 故障退避）
ConfigKeys 白名单 · initDatabase

原因：Snippets 无 D1 绑定能力，配置改为拉取主后端 /api/node-config（见改造章节）。

删除
配置推送接收（/api/sync/receive-config）
约 900 字节

删除的函数：

handleSyncConfig · safeEqual · readCappedBody
路由：POST /api/sync/receive-config

原因：Snippets 子端不接收主端推送，配置由子端每 5 分钟主动拉取 /api/node-config。推送通道仅 Worker 子后端需要。

四

完整保留的功能（官方原版原样）

9 大模块

以下功能与官方原版完全一致，未做任何精简或改动。

保留
WS + XHTTP 双传输
核心
  • WS：handleWebSocketConn，含 0-RTT 早期数据（sec-websocket-protocol / Referer 双通道回退）
  • XHTTP：handleXwebPost，POST application/grpc，stream-one 双向单流，1MB 桥
  • 路由：Upgrade: websocket → WS；POST + grpc → XHTTP
保留
VLESS 协议解析与认证
parseProtocolChunk
  • 协议头：Ver(1) + UUID(16) + OptLen(1) + Opt(N) + Cmd(1) + Port(2) + AddrType(1) + Addr(N)
  • UUID 恒时校验（getUuidBytes），支持 IPv4/域名/IPv6 三种地址类型
  • cmd=1 TCP / cmd=2 UDP（53 端口转 DoH）/ 其他 cmd 回挡板
保留
官方反代池（拆字写法原样保留）
OfficialProxyBase
OfficialProxyBase = 'p'+'r'+'o'+'x'+'y'+'.'+'z'+'j'+'c'+'l'+'o'+'u'+'d'+'.'+'u'+'s'+'.'+'c'+'i'
officialProxyHost(colo)：colo 子域 + 裸域双层
TierSub = 0, TierBase = 1：colo 子域优先，失联回落裸域

与官方原版完全一致，拆字避明文扫描的写法原样保留。

保留
三方反代池（拆字写法原样保留）
SenflareLink / ProxyIPPool
SenflareLink = 'S'+'e'+'n'+'f'+'l'+'a'+'r'+'e'+'L'+'i'+'n'+'k'+'.'+'k'+'d'+'n'+'s'+'.'+'f'+'r'
ProxyIPPool：18 地区（HK/TW/JP/KR/SG/IN/GB/FR/DE/NL/SE/FI/PL/RU/CH/LV/US/CA）
stickyShuffle：同目标确定性乱序（会话粘住同出口）
保留
两模式出站（auto / global，fixed 归一）
applyOutboundRules
  • auto 智能分流：CF 直连优先 → 失败切反代/链式 → 保留兜底反代
  • global 全局代理：固定出口语义（须 CUSTOM/LOCAL 列表型），不保留兜底
  • fixed 旧值自动归一为 global（两模式制）
  • forceProxy = outbound === 'global' || !!inlineExit
  • 兜底反代仅 outbound === 'auto' 时保留
保留
智能出站候选解析
resolveProxyCandidates
  • OFFICIAL：官方反代双层（colo 子域 + 裸域）
  • CUSTOM / LOCAL：自定义出口池（内联 + API 直链，base64 自动解码，5min 缓存）
  • 固定地区码：18 地区池精确匹配
  • AUTO：同区池域名（按 cf.country 筛选）
保留
竞速拨号 + 失败记忆 + 看门狗
raceDial / manualPipe
  • 竞速拨号：批 6 并发，3s 建连超时，首包写最快者，败者即关
  • 失败记忆：拨败 30s TTL + 指数退避（BlackholeBase 60s → 10min 上限）
  • 首字节看门狗：EMA 自适应阈值（10s 下限 / 20s 上限），黑洞标记
  • BYOB 下行管道：32KB 聚合 / 1ms 刷出 / 448KB 水位
  • 上行写手：小包攒 32KB / 2ms 出帧，超帧直通
  • 微任务环形队列：2048 槽位，8MB 字节上限
保留
DoH 劫持（53 端口 TCP/UDP）
dohQuery / feedFrames
  • 双端点竞速（Cloudflare + Google）+ 250ms 错峰
  • 粘性端点（dohPreferred）：上次赢家优先单发，失败升级全端点竞速
  • TTL 缓存（60s）+ 过期缓存兜底（10s）
  • TCP-DNS 空闲 5 分钟发 1000 关闭
  • 支持面板自定义 DoH URL（Doh 配置项）
保留
首页伪装反代 + 版本查询
handleFakePage / apiVersion
  • 伪装页：非代理请求反代到 https://www.xinhuanet.com/，域名重写
  • 版本查询：GET /api/version 返回 v4.4.5-snippet（免鉴权）

何时用 Snippet 精简版
  • ✅ 部署到 CF Snippets（32KB 限制场景）
  • ✅ 不需要链式代理（反代/直连已足够）
  • ✅ 配置由主后端统一管理（拉取模式）
  • ✅ 需要 WS + XHTTP 双传输
替代
何时用官方原版
  • ⚠️ 部署到 Worker（无 32KB 限制）
  • ⚠️ 需要链式代理（Socks5/HTTP 上游）
  • ⚠️ 需要D1 直读（低延迟，不走 HTTP 拉取）
  • ⚠�️ 需要推送接收（主端推送而非子端拉取）
