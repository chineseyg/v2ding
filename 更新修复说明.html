A. 继承自原版 4.4.5 的 Changelog 变更（4 项 + 1 安全加固）

重构
出站模式三并二：fixed 并入 global
#CL-1

原三模式（auto / global / fixed）精简为两模式，新语义：

智能分流（auto）：CF 直连优先，直连失败自动切反代/链式中转，保留兜底反代回退
全局代理（global）：开启链式代理时出站流量全部走链式；否则 CF 直连优先、仅 CF 系网站固定 IP，不保留兜底反代回退

主子后端同步变更：applyOutboundRules（fixed→global 归一 + 全局未开链式=固定IP语义）、forceProxy（全局+链式才走链式）、兜底反代仅智能分流保留、pinExit（fixed→global）、出站模式标签文案。

优化
部署推送 5s+8s 重试助手
#CL-2

一键/批量部署绑定新域名后，DNS 记录与边缘证书生效需时间，立即推送会失败。新增 pushConfigAfterDeploy 助手：

  • 推送前等 5 秒，日志标注「新绑域名等待 DNS 生效」
  • 推送结果仍有失败域名时再等 8 秒重试一次，取最好结果
  • Worker / Pages 两部署链共用同一补推助手
精简
删除订阅生成的节点数据源拉取缓存
#CL-3

移除 ipListCache / ListTtl / remoteAllOk，resolveIpList 改为即拉即用（保留并发去重）。优选/反代列表（含远端直链与 sub:// 探测）每次下发均为最新。配置保存处的 ipListCache.clear() 一并移除。

不受影响：配置加载缓存（nodeConf 5分钟TTL）与面板 Cache 开关的其他用途。
文案
主子后端清理代理协议相关文案描述
#CL-4

出站模式注释更新为两模式语义；子后端 Outbound 注释更新；outboundLabel 去除 fixed 选项。

安全
raw 凭据安全校验（主子后端同步）
#CL-5

parseUpstreamAddr 增加 if (/[\s?]/.test(raw)) return null; —— 空格破坏 HTTP 请求行、? 截断内联路径，凭据不支持。主后端 + 子后端均落地。

二

Snippets 同步异常修复（线上排查 + 根治）

后端 4 项 + 前端 4 项

线上问题：同账户同域名下不同 Snippets 子后端，面板同步数据只显示第一个成功；停用第一个后第二个报错无法同步。经 agent-browser 登录排查 + 代码审计，定位 3 处后端缺陷 + 1 处前端 UX 缺陷，双向根治。

根因分析（线上实测确认）

缺陷 1 · getCfAllHosts 同域名去重丢协议

同域名多 Snippets 第二个的 type/proto 被静默丢弃

全局 seenAll 去重后，hostType/hostProto Map 只保留首个后端的值，第二个 Snippet 的协议（如 XHTTP）丢失。

缺陷 2 · pullBased 无 per-account 归属

Snippets 同步结果不可见，前端无法区分哪个成功

pullBased 是扁平域名数组无 account 归属；ok/fail/versions 永不含 Snippets。同域名时前端按域名去重 → 只显示第一个。

缺陷 3 · Snippet domains 空被掩盖（报错根因）

domains 空时零贡献，被其他账号掩盖；停用后暴露为 null

线上实测数据： Snippet A (sfnode): domains=["sfnode.an226.pp.ua"] ✅ → 贡献 pullBased Snippet B (cdqc4): domains=[] ❌ syncDomains=["cdqc4.an226.pp.ua"] → 零贡献 · A 未停用：A 贡献 pullBased，B 被掩盖 → 只显示 A 成功 · 停用 A 后：A 被 skip，B domains 仍空 → pullBased=[] → return null → 400 报错

根因：前端把节点域名填进了「数据同步域名」（标必填），但后端 Snippets 读 domains（订阅生成域名）→ B 的 domains 一直为空。

#FIX-1 · L509

修复

#FIX-2 · L1745

修复

#FIX-3 · L1764

if (!ds.length) ds = jsonOr(r.syncDomains, [])，与 getCfAllHosts 已有的回退逻辑对齐，防 domains 空导致 Snippet 被 null 掩盖。兜底已有错数据，无需手动迁移。

修复
apiNodesSync 正确语义 + 返回 per-Snippet 明细
#FIX-4 · L2196

纯 Snippets 场景不再返回 total=0 误导前端，改为按 Worker/Snippet 分别统计：

  • 仅 Snippets：N 个 Snippets 节点为拉取模式，配置已就绪，子端每 5 分钟自动拉取
  • Worker + Snippets：推送完成：Worker 成功 X/Y；N 个 Snippets 节点自动拉取
  • 返回值增加 pullBased + snippets 字段；push-config 部署 action 同步返回

前端修复（4 项，均在 js/admin-ui.js）

UX
账号卡片 Snippets 字段标注
#FE-C · L1768

Snippets 模式下「同步域名」标"选填"，「订阅域名」为空时标"待补"，引导用户补填节点域名。

UX
Snippets 保存确认文案对齐
#FE-D · L1696

根因闭环：后端修复（domains 空回退 + pullBased 带 account 归属）兜底已有错数据 + 前端修复（字段联动引导正确填写 domains + 同步结果展示 per-Snippet 明细）从源头杜绝填错字段 = 双向根治。
